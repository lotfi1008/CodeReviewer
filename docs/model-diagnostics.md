این نتایج سالم بودن ارتباط، اعتبارنامه و امکان دریافت پاسخ ساختاریافته را نشان می‌دهند. مدل استدلال تولید می‌کند. مصرف زیاد خروجی در نمونهٔ کوچک مشاهده شده است؛ مدت اجرای واقعی به ورودی و بار سرویس وابسته است. از لاگ قدیمی timeout به‌تنهایی نمی‌توان دلیل داخلی سرور را قطعی تعیین کرد.

اجرای قبلی Review سقف صریح توکن خروجی نداشت. اکنون MaxOutputTokens در پروفایل (پیش‌فرض ۲۰۴۸، قابل تنظیم ۲۵۶ تا ۸۱۹۲) به SDK ارسال می‌شود. زمان پاسخ، finish_reason و مصرف توکن گزارش می‌شود؛ پایان length با راهنمای تنظیم سقف خروجی گزارش می‌شود. این سقف تضمین نمی‌کند مدل پاسخ نهایی را در زمان مقرر تولید کند.

برای اجرای دوبارهٔ آزمون مصنوعی: در محیط Development برنامه را با `--DiagnoseModels true`، یا `--DiagnoseModels true --DiagnosticExtended true`، یا `--DiagnoseModels true --DiagnosticReview true` اجرا کنید. هر آزمون درخواست واقعی محدود به مدل می‌فرستد. کلید و متن استدلال چاپ نمی‌شوند.

## بررسی واقعی MR شمارهٔ ۴

اجرای `a9bf8214-ba1d-4feb-b2e4-d7c9dbe13fc8` با پروفایل تشخیصی یک فایل، مهلت مدل ۹۰ ثانیه و مهلت کل ۱۲۰ ثانیه در SQL Server ذخیره شد. فایل ChangeDashboardFileValidator.cs در ۵۶٫۸ ثانیه پاسخ گرفت: پایان stop، ورودی ۳۲۰ توکن، خروجی گزارش‌شده ۳۲۵۱ توکن، صفر یافتهٔ پذیرفته‌شده. فقط یک فایل بررسی شده است؛ این نتیجه تأیید کل MR نیست.

### ناهماهنگی سقف خروجی

سقف درخواستی این اجرا ۲۰۴۸ بود، ولی مصرف گزارش‌شده ۳۲۵۱ است. آزمون محلی رهگیری درخواست SDK (`ModelWireTests`) ثابت می‌کند SDK پارامتر `max_completion_tokens=2048` می‌فرستد و `max_tokens` نمی‌فرستد. آزمون‌های خام بالا از `max_tokens` استفاده کرده‌اند. بنابراین پشتیبانی پراکسی از پارامتر جدید یا نحوهٔ شمارش توکن باید بررسی شود؛ بدون لاگ سرور نمی‌توان یکی از این دو را قطعی دانست. برنامه اکنون این اختلاف را به‌صورت Warning در لاگ SQL نمایش می‌دهد. تبدیل خودکار پارامتر برای تمام ارائه‌دهندگان انجام نشده، چون قراردادهای آن‌ها یکسان نیست.

جمع‌بندی شواهد: ارتباط و توکن معتبرند؛ تولید استدلال و تأخیر زیاد دیده شده؛ پاسخ همین فایل نزدیک مهلت پیش‌فرض ۶۰ ثانیه است. برای نسبت دادن timeoutهای قبلی به صف سرور، کندی تولید یا ناسازگاری پارامترها، لاگ پراکسی/سرویس مدل در زمان همان درخواست‌ها لازم است.
